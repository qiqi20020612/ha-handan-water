# 邯郸供水

适配 **Home Assistant 2026.10** 的独立自定义集成，domain：`handan_water`。通过供水户号只读查询账户、水表账单和缴费记录；不需要微信、openid、浏览器或额外 Python 依赖。

2026-10-21 已在 HA **2026.10.0、2026.10.1、2026.10.2** 分别通过完整自动化测试，每版 78 项；CI 持续运行这三个版本。v0.1.0 发布说明及准备流程见 [发布说明](docs/RELEASE_NOTES_0.1.0.md)和[发布流程](docs/RELEASING.md)。

2026-10-19 已用独立客户端实测：200001、200005、200008、200020 均可在不带 Cookie、Authorization、openid、Origin、Referer 的情况下查询提供的账户。HTTPS 探测超时，HTTP 可用；这不保证其他账户和未来服务器策略相同。详细证据见 [协议审查](docs/PROTOCOL.md)，历史处理见 [实现设计](docs/DESIGN.md)。

**隐私：HTTP 会明文传输户号和返回的账户资料。** 配置先尝试 HTTPS，只有你勾选同意风险后才允许回退到 HTTP。不会关闭证书校验，也不会自动跟随重定向。户号保存在 HA 自己的配置条目中；本地历史包含水表编号和账务数据，请将 HA 备份视为私密资料。集成不记录请求/响应、姓名、地址、电话、openid 或服务器错误原文。

## 安装

### HACS 自定义仓库

仓库地址：[qiqi20020612/ha-handan-water](https://github.com/qiqi20020612/ha-handan-water)。公开测试仅保留按已核实协议生成的合成数据，不包含真实账户的标识、用量、读数、金额或交易日期。

1. HACS → 右上角菜单 → 自定义仓库。
2. 填写 `https://github.com/qiqi20020612/ha-handan-water`，类别选择“集成”。
3. 下载“邯郸供水”，重启 Home Assistant。
4. 设置 → 设备与服务 → 添加集成 → 搜索“邯郸供水”。

### 手动安装

把本仓库的 `custom_components/handan_water` 整个目录复制到 HA 的 `/config/custom_components/handan_water`，然后重启。不要把整个项目覆盖到 `/config`，也不需要编辑 `configuration.yaml`。

## 配置和实体

在 UI 输入户号（保留前导零）。默认仅允许 HTTPS；如当前服务无法建立 HTTPS，可在理解明文风险后勾选 HTTP。验证成功才创建条目。每个户号添加一次，不同户号分别配置。

条目菜单的“重新配置”重新验证原户号和传输方式；为保护已有统计身份，它不将旧户号改绑到另一个家庭。其他户号请单独添加。条目标题使用账户哈希短标识，不显示真实户号。

| 设备 | 默认启用 | 默认关闭 / 诊断 |
| --- | --- | --- |
| 账户 | 账户欠费、预存余额、最近缴费金额、历史同步状态；刷新数据、恢复历史同步按钮 | 最近缴费应收金额、最近预存款抵扣、最近预存款变动、历史缴费记录、网站用水分析、最近成功刷新 |
| 每块水表 | 累计水表读数、本期用水量、本期账单应收金额、最近抄表日期、历史账单 | 已知账单累计应收 |

- 依据 `rlmcode` 自动发现每块表，分别创建设备；实体 unique_id 不依赖账单排序、数组下标、实体名称或账期。
- 每 24 小时更新，手动“刷新数据”会重新查询并同步历史；“恢复历史同步”只重试已有本地历史，不调用供水写接口。
- 选项可以开关历史导入、缴费查询、网站分析，以及历史实体属性最多显示条数（1–120，默认 24）。改选项会重新加载条目；此显示上限不裁剪持久化账本。
- 为适应 HA Recorder 的属性大小限制，较长历史可能提前截断属性展示；完整账本仍保留，实体状态显示已知记录总数。
- 历史账单按表保存真实起止日期、起止读数、用量、应收、缴清标记、滞纳金字段及全部费用分项；历史缴费保留账户级实缴、销账、预存变动和实际交易时间。不对缺少水表编号的销账明细强行分表。
- 不把账户 `RecentWater` 或 200020 网站趋势当作两表总量。网站分析仅为可选诊断。
- 核心查询失败会使依赖数据的实体不可用，旧值不冒充新数据；附加缴费/分析失败只影响对应实体。空列表与失败分开，缺失/空金额不转换为零。
- Recorder 读取/写入失败、超时或提交未确认时，“历史同步状态”显示失败并保留诊断信息；供水数据及抄表校验有效时，累计水表读数保持可用。抄表修订、读数回退及已同步历史冲突仍会阻断相关读数和统计，可用“恢复历史同步”重试暂时故障。

## 能源面板（水资源及费用）

已核对 HA 2026.10.2 的 Recorder、Energy 后端及其对应前端 20260930.4 的水资源配置对话框：支持水量统计及独立累计费用统计；选择外部水量统计时固定单价和单价实体不可用，应使用费用统计。

1. 保持 HA 原生 Recorder 可用，等待“历史同步状态”为“同步完成”。不需要更改其他集成或 HA 配置。
2. 在任一水表实体属性中查看“历史水量统计ID”和“历史应收统计ID”。ID 形如 `handan_water:<稳定哈希>_water` / `_cost`，显示名包含对应水表编号。
3. 设置 → 仪表盘 → 能源 → 水资源 → 添加水资源消耗。每块水表分别添加其“历史累计抄表观测”外部统计。
4. 费用选择“使用跟踪总费用的实体/统计”（具体中文随前端翻译），选择**同一水表**的“历史累计账单应收”。费用单位为 CNY；请核对 HA 显示货币。也可选择不跟踪费用。
5. 不使用固定单价。应收 rlje 和实缴 ppayment 不相等，预存增加也不是水费应收。能源面板费用为截至抄表日已知账单应收，实际现金缴费请查看账户缴费实体。

“累计水表读数”本身也满足 `m³`、`device_class=water`、`state_class=total_increasing`，可以作为从安装后开始的能源来源；其 Recorder 变化时间是 HA 收到新账单的时间。若需要旧历史，请使用上面的外部统计。**同一水表不要同时添加实体和外部统计两个来源，否则会重复。**

### 历史的时间精度

源站只提供约双月的抄表日期和账期用量，无法知道每天或每小时实际消耗。本集成只导入真实抄表日期的稀疏累计观测：日期按 Asia/Shanghai 00:00 对齐 UTC 整点，明确标注只有日期精度；首个已知起码作为 sum=0 基线，后续 sum=实际累计读数−基线。两块表始终分开。

**不补每日点、不均摊、不把 rlsl 作为某天实际用量导入。** HA 能源图按累计观测求差，其日柱可能把区间变化集中显示在端点附近，不能解释为那一天用了整期水量；跨抄表间隔的日/月图也没有真实逐日意义。请用“历史账单”的实际起止日期解释区间用量。精确每日能源图需要另有真实逐日/实时水表数据。

费用用每张 rlje 累计，时间标记是“截至结束抄表日已知的应收账单”；接口没有开票时间，不能声称这是实际计费发生时刻。滞纳金字段独立保留，不重复加到 rlje 中。实际缴费交易时间只保留在账户记录，不拿来伪造每表费用。

## 历史安全与恢复

- 滚动一年窗口之外的已知账单继续留在私有 Store，不因下次查询遗漏旧行而重置基线。首次只能导入服务器实际返回的历史，不宣称覆盖更早生命周期。
- 按账单/交易标识哈希去重；同日同读数合并。重复轮询、重启、重新加载和重新开启导入不会再次累加。
- 导入绝对 state/sum，先保存账本，再使用官方 `async_add_external_statistics`，等待 Recorder 提交并回读核验后保存同步检查点。中途失败可通过“恢复历史同步”幂等重放；Recorder 缺失的点也可从账本恢复。
- 已同步历史被修改、补入历史端点、相同区间出现另一张疑似补发账单，或者同编号读数回退，会暂停受影响序列。另一块表正常同步。新编号换表自动建立新设备；同编号归零没有换表凭据时不猜测新周期。
- “恢复历史同步”是故障重试，**不会强制接受矛盾数据、清空基线或覆盖人工编辑的统计**。若看到“需核查”，先保存 HA 备份，核对真实水表/账单，再依据修订证据处理。此版本没有自动消解同编号换表或历史修订的工具。
- API 没有撤销清单/完整性标志，不能区分窗口漏返、暂时遗漏与账单撤销；本地账本保留旧数据，不擅自删除或冲减。请用真实账单核对撤销场景。
- 卸载/重载保留账本。删除配置条目会删除该条目的私有账本；Recorder 长期统计保留，可由你在 HA 开发者工具“统计”中管理。重新添加前建议备份原账本；若旧统计与新窗口基线不一致，会保护性暂停覆盖。

## 常见日志

旧版本若出现 `via_device` 参数弃用警告，请通过 HACS 更新或重新下载 `main` 分支，然后重启 HA。修复版使用账户设备的注册 ID 关联水表，沿用已有设备、实体和历史。官方移除旧参数的计划为 HA 2027.8，见[设备注册表迁移说明](https://contributors.home-assistant.io/blog/2026/08/24/device-registry-follow-up-changes/)。

## 本地测试

推荐使用 Python 3.14 最新补丁版本（本地验证 3.14.8）；HA 2026.10 要求至少 3.14.2。公开测试完全使用合成 fixture，不访问供水服务或现有 HA。可用 `python3 scripts/generate_fixtures.py` 重建响应。

```sh
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements_test.txt
.venv/bin/pytest -q
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

默认解析到已验证的最新补丁 2026.10.2。测试其他已支持补丁时，在独立虚拟环境安装 `-r requirements_test.txt "homeassistant==2026.10.0"` 或 `2026.10.1`；解析器会选择与 HA 精确匹配的测试插件，不能强制混装不同版本。

覆盖精确请求封装、缴费日期逆序、业务码/空数据/结构变化、微信身份缺省、HTTP 风险同意、两表隔离、多账户、配置/重新配置/选项、刷新失败恢复、真实 Recorder 写入与重放、重启基线、疑似补发及读数修订等。具体执行结果见 [验证记录](docs/VALIDATION.md)。

本集成与供水公司无隶属关系，仅实现经过审查的四个只读查询；不实现付款、充值、绑定修改、资料修改、上传或网站日志上报。
